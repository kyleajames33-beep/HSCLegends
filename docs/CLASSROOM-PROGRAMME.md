## V2 independent-review corrections

The first independent programme review found two client callback gaps. V2 keeps refresh available during an unresolved answer (and during final-score loading), with separate latest-read ownership rather than the answer busy flag. A second explicit refresh can supersede a hung first read. Each rendered answer/refresh/practice callback retains its originating connection generation, owner, room and player; it cannot adopt a replacement room's current generation when invoked later. Reads and answer settlement recheck that binding, and answer settlement additionally requires the original active question.

Six added offline tests cover held answer success/error after catch-up to a new question or completion; retained closures after a different room or the same room under a new generation; account change/unmount; held refresh settlement after replacement; and repeated explicit refresh. These remain source/hook/transport-double checks, with all backend blockers unchanged. V2 originally had no fresh build: its earlier attempt was blocked fetching the existing Google Fonts. The 2026-10-05 reconciled candidate now passes the production build with loopback/placeholder Supabase values. This is compilation/prerendering evidence only; it does not establish connected gameplay or backend readiness.
