# Classroom v2 guest recovery groundwork

`lib/classroom-v2/guest-recovery.ts` is an isolated staging candidate; it is not imported by the live classroom and does not create or authenticate guest accounts. It stores only a room ID and player ID, the corresponding actor ID, a caller-supplied project identifier and a local timestamp. Do not put tokens, answer receipts, names or question content in this selector store. These selectors are untrusted hints, not proof of identity or room membership.

Supply tab-scoped `sessionStorage` and a stable, unique identifier for the dedicated staging project. Save only after the server confirms a join. On recovery, obtain the current identity and generation from the auth layer, then supply `openClient` that creates a **fresh** owner- and generation-bound classroom v2 client using that same authenticated session. Recovery rejects a different actor/project, malformed data, a future timestamp and data at least six hours old. It binds the selectors and requests a server snapshot. A failed snapshot does not become a recovered game, and does not erase a hint that might be usable after a network failure. The server must independently authorize the participant.

Increment the generation on every authentication/session transition, including away from and back to the same actor. Dispose any returned client on auth transition, route teardown or replacement. A caller starting competing recovery attempts must supersede older attempts and dispose clients that are no longer used. The helper suppresses a response when the actor or generation changes during recovery; it does not manage UI attempts or provide an authentication provider.

Browser storage can be disabled, cleared, copied or tampered with. Anonymous users cannot recover a lost authentication session merely from these selectors; cross-device recovery, sign-in issuance, credential linking, revocation, abuse controls and real Supabase JWT verification remain separate work. The six-hour local limit is not a server expiry guarantee. The local tests use synthetic transports, not production data or real authentication.

Run the focused tests with `node --import ./tests/support/deny-network.mjs --test tests/offline/classroom-v2-guest-recovery.test.mjs`. The candidate remains disabled until a separately configured and reviewed staging environment and identity lifecycle are available.
