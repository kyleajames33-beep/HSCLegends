# Classroom review follow-up

The supplied review identified real staging usability issues and correctly noted that import validation does not certify scientific accuracy, syllabus versions or module mappings. The review could not access the source Chemistry bank, so it is not a Chemistry content audit. Local sample questions and imported drafts still require educator review.

A later external review examined the 12 local equilibrium sample questions in `prototypes/lab-tycoon/src/content.mjs` and reported no outright scientific errors, while noting that syllabus scope was not confirmed. This is useful review input, not educator approval or a verified syllabus mapping. The same review identified that the disposable Supabase smoke-test gateway guard accepted wildcard network bindings; the guard now rejects them for both database and gateway containers. The proposed local stack commands were not executed: prior isolated attempts and their unresolved networking failures are recorded in `CLASSROOM_STAGING_AUTH.md`.

The staging page now lets an actor leave a room locally and clear that room's recovery shortcut; leaving does not end or alter the server game. It distinguishes failures before a room exists from failures inside a room, hides host controls for anonymous guests, exposes a retry for unavailable authentication, shows question progress and makes an estimated timeout visible. Student answer buttons are disabled when the local estimate reaches zero; the server remains authoritative and network delay means the estimate may be inaccurate. Module and syllabus fields are still unverified free text, now explicitly described as such in the importer. The updated staging candidate supplies a bounded question total; older snapshots show only the question number.

Synthetic SQL and disposable PostgreSQL coverage now explicitly check a new actor joining after start, a repeated join with a changed alias (the original alias is retained), and host revocation during an active question. They confirm existing students can still see the active room after host revocation; there is no host handover. The PostgreSQL test also checks another host cannot take control and an unanswered question remains private after completion. Concurrent duplicate answers and foreign actor denial were already covered by that test. It is intentionally separate from `npm test` because it requires a Docker daemon and a local Postgres image; run it as documented in `prototypes/classroom-v2/README.md`. The mock actor used in these tests cannot prove real authentication. Real Supabase, cross-device session loss, timeout boundaries, rate limits and production rollout remain open.
